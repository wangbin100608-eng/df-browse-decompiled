## 3. 模型 B：目标检测器（YOLOv8n 迁移学习）

- 迁移学习：YOLOv8n COCO 预训练权重
- 40 epoch，训练耗时 165.7s（CPU）
- 详细指标：`experiments/detector_yolov8n/evaluation.json`

| 指标 | **测试集（4 帧/37 实例）** |
|---|---|
| Precision | **0.7126** |
| Recall | **0.3419** |
| **mAP50** | **0.5126** |
| **mAP50-95** | **0.3049** |
| 平均推理耗时 | **108.7 ms/帧**（CPU，含预处理+推理+后处理） |

**局限（如实）**：检测训练仅 6 帧、验证 1 帧、测试 4 帧——样本严重不足，Recall 偏低（0.34），mAP 仅供参考，不足以宣称生产可用。失败案例可视化在 `experiments/detector_yolov8n/failures/`。

**选择哪个模型**：分类器 A 指标明显更好（0.86 vs 检测 mAP 0.51），但其输入是裁剪好的图标；检测器 B 能在完整画面定位。实际部署选择 **检测器 B**（APK 场景是完整游戏画面），分类器 A 作为"给定裁剪"的复核路径保留。这是按数据量与实测结果的选择，不是预设。

## 4. Android 集成与实机验证

### 4.1 集成内容

- 导出 ONNX：`ml/models/detector_yolov8n.onnx`（12.8 MB，输入 `[1,3,640,640]`，输出 `[1,20,8400]`）
- 新增 `YoloDetector.kt`：ONNX Runtime Mobile 推理 + 置信度过滤 + NMS
- assets：`detector_yolov8n.onnx`、`yolo_labels.json`（16 类 → item_id）、`detector_version.txt`
- `ScanProcessor`：YOLO 路径优先，dHash 兜底；YOLO 模式下**绕过 OCR 切格**（不调用 GridOcr）
- 低置信度结果（<0.55）进入待确认队列；未知物品不强制匹配
- `./gradlew assembleRelease --offline` 编译通过，APK 74 MB

## 6. 结论与限制

- 分类器在独立测试集 86.5%，检测器 mAP50 0.51——**数据规模决定上限**（98 条标注、11 张检测帧）。
- 实机验证了 ONNX 部署全链路，但检测效果距生产可用有差距，需扩充真实帧标注（目标每类≥30、检测帧≥100）。
- 普通非武器类参考图片本体仍未本地持有（第一阶段缺口 G1），本次以真实游戏帧裁剪训练绕过了该缺口，但泛化到未出现物品仍受限。
