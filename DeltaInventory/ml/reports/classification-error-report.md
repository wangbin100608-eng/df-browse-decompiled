## 3. 误差模式归类

1. **低置信度主导**：6 条错误 conf 全部 ≤0.31（阈值 0.35/0.55），说明模型"知道自己错"——APK 的低置信度过滤能拦住，但会导致这些物品漏检。
2. **低频类别主导**：DICH（2 条错）、黑鹰（1 条错）都是训练样本仅 2 的类；样本≥5 的类几乎不出错。
3. **形态相似混淆**：注射器↔弹药盒（都是长条/小盒状）、头盔↔弓（深色大件轮廓）。
4. **非同外观混淆**：这些错误不是"87 组同 phash"的物理上限导致，而是训练样本不足 + 背景干扰。

## 4. 检测器 B 的错误（部署模型）

- 训练 test：P 0.7126 / R 0.3419 / mAP50 0.5126 / mAP50-95 0.3049。
- 独立测试实机：检出强效注射器 1 件（conf 0.59），远少于画面中实际物品数——**漏检（低 Recall）是检测器主要误差**。
- 失败案例图：`ml/experiments/detector_yolov8n/failures/`（4 张 test 预测可视化）。
- 北极星 class 10 的 item_id 为空，`ScanProcessor` L116 `findById("")` 会跳过——即使检出也无法确认（源码核查发现）。

## 5. 错误标签与审核驳回

- 独立测试标注 38 条中 7 条被人工审核驳回（框到空白/UI文字），其中 CAT止血带 2/2 全部驳回。
- 这些错误框若进入训练会污染模型——本阶段已剔除并保留 reject_reason。

## 6. 结论

分类错误是**数据驱动**（低频类+低置信度），不是算法选型错误。低置信度过滤机制有效（拦住全部 6 条错误），代价是漏检。要降低错误率需：补低频类样本（每类≥8）、增加形态相近类的难负样本、对 CAT 类重新框选。
