# 数据集缺口报告（Dataset Gap Report）

> 基于 `asset-audit-report.md` 的审计结论，列出"现有数据 → 训练一个能在真实游戏画面识别物资的模型"之间的全部缺口。按优先级排序。**本报告只列缺口，不含训练执行方案（见 `recommended-training-plan.md`）。**

## 缺口总览

| # | 缺口 | 当前状态 | 需求 | 优先级 |
|---|---|---|---|---|
| G1 | 物品参考图片本体 | 0/1663 本地持有 | 至少覆盖目标类别的 CDN 原图 | P0 |
| G2 | 真实域整帧标注 | 19 条孤立裁剪，无整帧全标注 | 每张训练帧标注所有物资 bbox | P0 |
| G3 | 每类样本量 | 7 类仅 1 个样本 | 每类 ≥8–12 个真实裁剪 | P0 |
| G4 | 训练脚本 | `train_detector.py` 缺失 | 可用的检测器训练脚本 | P0 |
| G5 | 裁剪/标注工具 | 无 | 半自动标注 + 裁剪 + 增广脚本 | P1 |
| G6 | 独立验证集 | 无 | 与训练集不同帧/不同对局的标注帧 | P1 |
| G7 | 同外观物品区分特征 | 87 组 phash 相同、hist 退化 | 能区分同外观组的特征或上下文 | P2 |
| G8 | 尺寸标准化 | 参考图 143–336px 不等 | 统一预处理规范 | P2 |

---

## G1 — 物品参考图片本体缺失

- **现状**：仓库只有 22 张 UI 图（favicon/占位图/安全箱尺寸），1663 件物品的图片全部是 `https://df-assets.lza11111.com/playerhub/60004/object/p_<id>.webp` URL，无本地文件。
- **影响**：无法做基于图片的任何训练/增强/质检；`item-features.json` 只有哈希和直方图，不是图像。
- **需求**：下载 URL（模板已验证可用，本机曾成功下载 15 张，11–21 KB/张）。若训练普通非武器类，优先下载 `props`(795) + `protect`(98) = 893 张；若目标只覆盖已出现物资，15 张已够起步。
- **注意**：图片版权归腾讯/《三角洲行动》，仓库已声明仅本地研究使用；不重复下载已持有的 15 张。

## G2 — 真实域整帧标注缺失

- **现状**：`research/train/real_labels.jsonl` 有 19 条 bbox，但每条是孤立物品裁剪坐标，没有一张完整帧上"所有物资都标注"的记录。
- **影响**：训练分类器够用（给定裁剪→类别），训练检测器（整图→bbox+类别）不够。APK 的 `VisionEngine.detect` 需要检测器。
- **需求**：对 13 张高清帧逐张标出所有可见物资的 bbox 与类别，形成 yolo 格式整帧标注。每张帧的背包区、口袋、安全箱、战利品区都要覆盖。

## G3 — 每类样本量严重不足

| 类别 | 当前真实样本 | 建议 |
|---|---|---|
| 5.56x45mm CINDER | 4 | ≥10 |
| 强效注射器 | 4 | ≥10 |
| 5.56x45mm M995 | 3 | ≥10 |
| UZI冲锋枪 / M1911 / 北极星 / 突击手防弹背心 / MHS 战术头盔 / 武士防弹背心 / GA野战背包 / CAT止血带 | 各 1 | 每类 ≥8 |

- **影响**：跨视频验证 v1→v2 仅 30%，主因是 v2 独有类在训练集只有 0–1 个样本（类别覆盖问题）。
- **建议**：优先补 8 个"只有 1 个样本"的类别；同源 3 折目标 ≥85%。

## G4 — 训练脚本缺失

- **现状**：仓库 `tools/` 有 `build_features.py`（下载+特征提取）、`import_assets.py`、两个构建脚本；README 和 `models/README.md` 提到的 `tools/train_detector.py` **不存在**（raw 404）。
- **需求**：检测器训练脚本，输入输出契约对齐 APK：`[1,3,640,640] → [1,100,6]`，opset 13。
- **已有替代**：`research/train/scripts/` 下有分类器训练/导出脚本（`train_real_merged.py`、`export_onnx.py`），可作为起点扩展为检测器训练。

## G5 — 裁剪/预处理/标注工具缺失

- **现状**：无可视化标注工具、无统一裁剪脚本、无增广流水线（现有 `gen_data.py` 是合成数据脚本，路线已证伪）。
- **需求**：
  - 标注：输入高清帧 + 网格坐标 → 输出 bbox/类别（可复用 `real_labels.jsonl` 格式）
  - 裁剪：bbox → 64×64（分类器）/ 640×640 拼图（检测器）
  - 增广：亮度/对比度/JPEG/小幅平移，**在真实域内**，不引入 CDN 纯图标合成
  - 质量检查：裁剪预览拼图（已有 `crop_check*.png` 的做法）

## G6 — 独立验证集缺失

- **现状**：19 条标注来自 2 个视频的 2 张主帧（v1_2.5、v2_2.5），同源 3 折划分，训练集与验证集画面高度相似。
- **影响**：同源 68.4% 可能偏乐观，泛化到其他对局未知。
- **需求**：至少 1–2 张不同时间点/不同对局的真实帧作为独立测试集，标注全物资。

## G7 — 同外观物品区分特征缺失

- **现状**：87 组共 350 件物品 phash 完全相同（最大组 16 件）；hist 1271/1663 只有 1 个非零桶。
- **影响**：即使识别流程完美，纯视觉特征也无法区分这些物品（物理上限）。
- **需求**：对同外观组，使用上下文信息（所在格子/背包区域/与其他物品的组合）或高分辨率局部纹理（磨损、角度）建立次级特征；或接受"只能返回组内任一物品"并在 UI 标注。

## G8 — 尺寸标准化缺失

- **现状**：本地 15 张参考图尺寸从 143×242 到 336×336 不等，宽高比 2:1~1:2。
- **影响**：直接训练会导致缩放失真；特征库用步长采样规避了这个问题，但 CNN 需要统一规范。
- **需求**：明确预处理规格（长边 padding 到正方形、保留 alpha 预乘语义、记录原始宽高）。

---

## 缺口与成功标准的关系

成功标准（已确认）：APK 在两个视频上的识别与正确清单一致。

要达成它，最小闭环是 **G1 + G2 + G3 + G4**（有图、有真实整帧标注、每类够样本、有训练脚本）；G5/G6 提升可靠性；G7/G8 决定上限与工程规范。当前所有 8 项均未完全满足。
