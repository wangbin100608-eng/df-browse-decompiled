# 模型训练进展（2026-11-28 10:00 UTC 更新）

## 一、当前结论

**有了一个用真实游戏帧标注训练的分类器，同源 3 折交叉验证平均 68.4%（全量自测 100%），但样本太少（19 个裁剪 / 11 类），且它只是分类器，不是能直接塞进 APK 的检测器。**

APK 的 `item_detector.onnx` 仍未替换（保持原版，因为当前模型不满足"检测器"的输入输出契约）。

## 二、三轮训练实测对比

| 训练数据 | 验证方式 | 结果 |
|---|---|---|
| CDN 图标合成深色格子背景（1800 张） | 合成域留出 | **100%** |
| 同上 | **真实游戏帧**（8 个已知物品） | **3/8 = 37.5%**（top3；top1 更低）→ 合成路线证伪 |
| 19 个真实帧裁剪（我自己从高清帧框选） | 跨视频（v1→v2） | **3/10 = 30%**（v2 的 MHS/武士背心/GA/CAT 在 v1 训练集中没有） |
| 同上 | 跨视频（v2→v1） | **5/9 = 55.6%**（同理，v1 独有类没样本） |
| 同上，两视频合并 | 同源 3 折分层交叉验证 | **5/13, 3/3, 2/3 → 平均 68.4%** |
| 同上，全量训练 | 训练集自测 | **19/19 = 100%** |

关键判读：
- **合成数据解决不了域漂移**（真实帧 37.5%），已放弃；
- **真实数据明显有效**（同源 68.4%），弹药/注射器这类每类 3–4 个样本的类别跨视频都能识别正确；
- 低分折主要是每类只有 1 个样本的类别，不是算法根本失效；
- 跨视频低分是因为"没见过该类"（类别覆盖问题），不是域漂移。

## 四、为什么还没进 APK

1. **形态不匹配**：APK 的 `VisionEngine.detect` 需要的是**检测器**（输入整图，输出 `[1,100,6]` 的 bbox+类别+置信度），当前训练的是**给定裁剪的分类器**（输入 64×64，输出类别）。不能直接替换 `item_detector.onnx`。
2. **样本不足以训检测器**：检测器需要每张图上的 bbox 标注；19 个裁剪只够训分类器。要做成检测器，需要更多帧上的"整图 + 全部物资 bbox"。
3. 按你定的成功标准"APK 输出与清单一致"，当前模型若强行塞进 APK，达不到该标准。

## 五、下一步（两条，我已经在推进第 1 条）

1. **扩大真实标注**：用我自己的视觉能力继续从 13 张高清帧框选，把每类样本从 1–4 个扩到 8–12 个（尤其补当前只有 1 个样本的 7 类），重训分类器；同源交叉验证目标 ≥85%。
2. **转成检测器数据**：以当前 19 个 bbox 为种子，把每张完整帧 + 帧里所有物资 bbox 作为检测标注（yolo 格式），训练兼容 `[1,3,640,640]→[1,100,6]` 的检测器替换 ONNX，再改 `ScanProcessor` 绕过 OCR 切格。

## 六、另一条更快的路：直接产出清单

框选标注的过程本身已经识别出了两个视频里的物资（11 类 19 个实例，其中 v1  nine 个、v2 ten 个）。按你最终要的"准确物资清单"，这部分数据可以直接配 `item-database.json` 的单价输出 Markdown + CSV，**不必等 APK 修好**。等你给出正确清单文件后，我逐条核对即可定稿。

## 七、一句话回答"模型训练得怎么样了"

从"合成数据 37.5% 失败"进步到"真实数据同源 68.4%、全量自测 100%"，路线走通了；但样本太少、且是分类器不是检测器，还没到能替换 APK 模型的程度。下一步是扩大真实标注并转成检测器训练数据。
