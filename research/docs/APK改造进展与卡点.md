## 三、关键实测结论（这是卡点的证据）

### 3.1 APK 官方版三组实验全部 0 件

- CDN 纯图标 CINDER 铺屏：0 件
- v1 视频铺满+慢放：0 件
- v2 视频铺满+慢放：0 件
- 数据库 `item_instances`/`recognition_events`/`frame_records` 全 0；日志 271 次 SCVTF 跳过（OCR 降级）；无崩溃。

### 3.2 合成训练路线实测失败（决定性）

迁移性预检 `train/precheck_transfer.py`：

- 合成域 CNN：epoch 1 起验证准确率 **100%**（1800 张，15 类）；
- 真实游戏帧裁块（8 个已知物品）：top3 命中率 **3/8 = 37.5%**，top1 更低。
- 例：CINDER 真实格 → top1 竟是 M1911（1.00），CINDER 概率 0.00；UZI 真实格 → top1 UZI（1.00）蒙对。

**结论：用 CDN 图标合成深色格子背景训练，解决不了"纯图标域→游戏渲染格"的域漂移。** 这与仓库 accuracy-report 的 dHash 域漂移是同一个病根，只是把失效算法从哈希换成了 CNN。Q35 选的"合成训练"路线已被实测证伪。

### 3.3 模板匹配自动定位也不可靠

用 CDN 图标在真实帧做多尺度模板匹配：CINDER 0.732、注射器 0.663、UZI 0.719——分数低，且定位点可疑（CINDER 落到左下弹药区、注射器落到右侧信息区）。**用它自动生成真实域标注不可信。**

补充实测（自监督/伪标签预检，2026-11-28 09:42）：
- 霍夫线检测网格：检测到 88 条竖线/125 条横线，聚类出 30+ 个簇，UI 各种边框混杂，**无法自动分格**；
- CINDER 多尺度多位置模板匹配 + NMS：top 分数仅 0.55 左右，定位在 `(379,1389)`、`(224,1408)` 等左下弹药区，与真实 CINDER 位置（口袋区约 `x=660,y=600`）**完全对不上**。
- 结论：自监督伪标签方案也失败——模板匹配本身同样受域漂移影响，无法给真实帧打可靠伪标签。**Q40 选的这条路线已被实测证伪。**

至此三条"不用人工标注"的路线全部实测失败：合成训练（3/8）、模板匹配定位（分数低且错位）、霍夫自动分格（边框混杂）。**唯一剩下能产生可靠真实域标注的方式是人工框选**（路线 A）或你提供带坐标的清单（路线 B）。

## 四、为什么卡住（死结）

训练能在真实游戏帧工作的分类器，唯一可靠的输入是**真实帧里"物资名 ↔ 像素位置(bbox)"的标注**：

- 合成数据 → 实测迁移失败（3.2）；
- 模板匹配自动标注 → 不可靠（3.3）；
- 你给的正确清单 → 按 Q32 只有名称/数量/价值，**没有位置**；
- 你尚未提供那份清单文件，也没有带坐标的版本。

**没有真实位置标注 → 训不出能在真实帧工作的模型 → 换算法后 APK 仍会输出 0 件 → 达不到"与清单一致"的成功标准。** 这不是实现难度问题，是数据缺失。

3. 我用这些真实裁剪 + 数据增广训练分类器，重新做迁移性预检；
4. 若真实域准确率显著高于 37.5%，再训练完整检测器、替换 ONNX、改 ScanProcessor 绕过 OCR 切格、重编译验证。

1. **模型**：保持 `VisionEngine.detect` 输入输出 `[1,3,640,640]→[1,100,6]` 不变，训练兼容格式的检测模型，直接替换 `assets/models/item_detector.onnx`（Kotlin 推理端零改动）；
