## 3. 帧图中纯物品图标的像素尺寸与裁剪可用性

帧文件：`/root/盘点/frames/v1_2.png`、`/root/盘点/frames/v2_2.png`（`file` 与 Pillow 均为 1280×800 RGB PNG）。已用 read_image 目视两图。

定性判断：
- “纯物品图标”在这两张 1280×800 游戏帧里只是格子内一小块，典型 1×1 小格约 65–85 px 见方，图标本体（去掉背景/边框/文字/数量角标后）约 **40–80 px**（多数 50–70 px），大格里的头盔/背心约 **120–240 px**。这远小于 CDN 原图的 258–336 px 画布，也远小于 App 若按屏幕采集时的 1280×800 全屏输入。
- 因此：把这些小图标裁出来后必须上采样约 4–8 倍才能“铺满屏幕”喂给 App 采集；放大只能插值，不能恢复细节。更重要的是，报导中的失败域差异来自“深色背景 + 边框 + 文字标签 + 数量角标”的渲染格子，裁剪时若带入这些像素，5/5 的纯图标域结论不会迁移；紧贴物体边缘裁掉背景/文字在 1280×800 上操作余量很小。

量化证据（Pillow 对 v1_2.png 局部区域按与局部背景色差阈值统计；像素框为人工选取）：

```

v1_pocket_syringe_content content_wh (61, 45)  object_wh (61, 45)  mask_ratio 0.246
v1_chest_syringe_content  content_wh (69, 48)  object_wh (61, 48)  mask_ratio 0.252

```

这些数值包含少量背景/文字带，作为量级估计足够：小格图标内容集中在 60–80 px 宽、45–70 px 高，大格约 240×120 px。结论为“量级够肉眼读名，但不足以直接作为 300×300 级别纯图标原图使用，且能否跨到 App 识别取决于裁剪是否彻底去背景/文字”。
